# Coding 通用的编辑代码的要求
- 确保写的代码优雅且经典，不要有任何无用的和冗杂的代码，确保代码的可维护性和扩展性
- 所有改动需遵循通用化原则，尽可能不要采用特殊处理的方式
- 在合适的地方加上较充分的代码注释，因为恰到好处的注释能让其他用户更容易理解和维护代码
- 编辑代码时尽量不要删用户写好的注释，除非你觉得注释有大问题，需要改动
- 开发新功能和修复问题时，注意不要影响已有的功能逻辑
- 代码开发时候，尽量使用常规的标准化的通用的解决方案
- 在用户没有要求时，技术栈选型可以使用项目已有技术栈，需结合项目当前的风格进行开发

## Java 代码编写要求
- 包名尽量不要写入逻辑代码中，而是需要通过 import 引入的形式在 Java 文件最上方先引入

# Chatting 回复用户问题时的要求
- 回复用户问题时尽量简练且准确，但注意意思也要表达清晰！避免冗长多余的废话，以便帮助用户减少 token 消耗
- 看明白用户真正的疑问在哪（用户可能有很多背景知识并不了解），探明问题的内核，回答问题要贴近用户的思维，抓住本质
