# vue 前端开发模版

## 是否必须向用户确认
如果项目中该内容已经完成了一部分（如下所有需向用户确认的内容其实已经使用在项目中了），则延续用户所使用的技术栈能力继续标准化的开发即可，这种情况下无需向用户确认以下内容

如果项目中开发了部分的内容中，而且没有明确需要确认的如下技术栈能力，则必须要向用户确认：
- 使用 JavaScript 还是 TypeScript
- 使用 vue 2 还是 vue 3
- 使用的 node 版本

这是因为它们之间有对应关系：

| 技术栈 | 对应关系 |
|---|---|
| vue 2 | 对应 node 14/16，推荐 element-ui，使用 vue-cli 创建 |
| vue 3 | 对应 node 16/18/20，推荐 element-plus，使用 vite 创建 |
| js / ts | vue 2 和 vue 3 都兼容 js，vue 3 推荐 ts |

然后你需要向用户询问后端 API 的基础地址（这个信息用户不一定必须告知你）。如果用户告知了，则后续建立 demo 时可以用到；如果用户说还没有，那么你可以自己写样例形式。

## 跟用户说明
跟用户说明你要做什么事情，以及做事都步骤是啥样子的，向用户确认是否同意

## 非常标准化 vue 项目结构

如果用户已经有了项目的整体结构，那就用 vue 标准化的项目结构来补充用户目前已有的项目。如果用户的整体项目结构为空，那你更可以使用 vue 标准化的项目结构来初始化项目了。

包括项目中各种标准化的配置文件（配置文件注意也要比较标准的加上详细注释）

## 开发：内容的填充

你刚才补充完整体的项目结构，注意还需要填写其中最标准最简单化的例子，比如你需要配置好最简单标准化的：

- axios 请求封装（含请求/响应拦截器）
- vue-router 路由配置（至少包含首页和 404 页面）
- element-ui（vue2）或 element-plus（vue3）的全局引入
- 建立一个查询 User 相关的标准模版示例（如果用户已经告知了 API 则不需要写 User 这样的样例，则你需要直接写操作 API 的样例即可）：
  - 一个 UserList.vue 页面组件
  - 一个 user.js API 模块（含增删改查 4 种标准接口）
  - 使用表格展示数据，含分页
  - 使用对话框表单进行新增/编辑

## 最后输出

最后输出告知用户这是一个 demo 精简的示例，哪些地方需要用户调整的，比如：

- 后端 API 的基础地址
- element-ui / element-plus 的主题或按需引入配置
- router 中的路由路径
- UserList.vue 中的表格字段
- user.js 中的接口路径和参数

这些随着用户的业务而需要调整的地方你需要给用户指明出来。

## 注意

- 因为用户很有可能还没有后端服务，以及 API 地址如果本身也不是用户提供的，所以项目大概率调用接口会报错，所以一些地方你需要自己看着加上注释或 mock 数据，避免页面空白或报错
- vue 2 使用 `vue create` 创建项目，vue 3 使用 `npm create vue@latest` 或 `npm create vite@latest` 创建项目
- 如果用户选择 vue 2 + js，使用选项式 API 风格；如果用户选择 vue 3 + ts，推荐使用 `<script setup>` 组合式 API 风格
