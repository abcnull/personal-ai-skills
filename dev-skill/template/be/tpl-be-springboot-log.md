# springboot 后端开发日志模版

## 是否必须向用户确认
如果项目中该内容已经完成了一部分（如下所有需向用户确认的内容其实已经使用在项目中了），则延续用户所使用的技术栈能力继续标准化的开发即可，这种情况下无需向用户确认以下内容

如果项目中开发了部分的内容中，而且没有明确需要确认的如下技术栈能力，则必须要向用户确认：
- 使用 log4j2 还是使用 logback 日志框架（如果用户不确认，默认按照 log4j2 来配置）
- 向用户确认日志存放到机器上的什么路径下（如果用户不确认，就默认按照最标准化的服务器日志存放路径来配置）

## 跟用户说明
根用户说明你整体的配置方式，和步骤，向用户确认是否同意继续

## 开发：日志配置
- 你需要指定日志文件路径
- 使用 xml 来配置非常标准化的日志，包括普通日志，异常日志，以及做表转化的日志滚动等
- 配置日志 xml 需要加上非常充分的注释，方便用户清晰的知道每一步怎么配置

## 最后输出
- 最后告知用户日志的配置具体的功能
- 告知用户关键数据配置想要修改在哪改，以及怎么改配置
