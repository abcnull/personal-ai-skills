# springboot 后端开发模版

## 是否必须向用户确认
如果项目中该内容已经完成了一部分（如下所有需向用户确认的内容其实已经使用在项目中了），则延续用户所使用的技术栈能力继续标准化的开发即可，这种情况下无需向用户确认以下内容

如果项目中开发了部分的内容中，而且没有明确需要确认的如下技术栈能力，则必须要向用户确认：
- 所使用的 java 版本
- 想要使用 springboot 2.x 还是 springboot 3.x 版本

这是因为 java 版本和 springboot 有对应关系

然后你需要像用户询问 mysql 连接的配置信息（这个信息用户不一定必须告知你），如果用户告知来，则后续你建立 demo 时候可以用到，如果用户说还没有，那么你可以自己写样例形式

## 跟用户说明
跟用户说明你要做什么事情，以及做事都步骤是啥样子的，向用户确认是否同意

## 非常标准化 springboot 项目结构
如果用户已经有了项目的整体结构，那就用 springboot 标准化的项目结构来补充用户目前已有的项目。那如果用户的整体项目结构为空，那你更可以使用 springboot 标准化的项目结构来初始化项目了

请使用 application.yml 而非 application.properties

## 开发：内容的填充
你刚才补充完整体的项目结构，注意还需要填写其中最标准最简单化的例子，比如你需要配置好最简单标准化的:
- mybatis ORM，假定用户有一个 User 数据表，里头有 age 和 name 字段
- 使用 log4j2 日志配置
- 建立一个查询 User 相关的 Controller 标准模版示例，以及 Mapper 接口，以及对应的 Service 和 Entity
- Mapper 接口对应的 xml 文件中，要有“增删改查” 4 种标准的 demo 样例

## 最后输出
最后输出告知用户这是一个 demo 精简的示例，哪些地方需要用户调整的，比如数据库的表，数据库链接的用户密码，log4j2 的日志里头具体哪里的配置，以及 controller，service，entity，mapper 等代码，这些随着用户的业务而需要调整的地方你需要给用户指明出来

## 注意
- 因为用户很有可能就没有 User 表，以及连接数据库的配置如果本身也不是用户提供的，所以项目大概率跑不起来，所以一些地方你需要自己看着加上注释，避免项目启动问题
