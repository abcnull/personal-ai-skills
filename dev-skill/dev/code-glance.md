# code-glance

## 使用场景
当用户给出某处代码（片段/文件/文件夹/工作区），希望理解这处代码的逻辑、功能或实现细节时触发此 skill。

## 执行流程

### 1. 环境检测（可选加速）
检查是否可以使用 codegraph 快速索引代码：
```shell
# 判定是否有 codegraph 环境变量
codegraph -v

# 判定是否已建立索引
codegraph status
```
- 如果环境变量存在、已有索引、且 MCP 工具可用，则执行 `codegraph sync` 更新索引
- 否则不使用 codegraph，直接通过常规方式读取代码

### 2. 代码阅读与梳理
无论用户是否表达了代码难懂的原因，都需要：
1. **严谨阅读**用户指定的代码
2. **梳理清楚**代码的整体逻辑和细节
3. **不完全信任**代码逻辑和注释（可能存在 bug、漏洞或误导性注释）
4. **理解用户视角**：结合用户表达的难点（如有）或自行分析用户可能看不懂的地方

### 3. 难点分析与讲解输出

#### 3.1 整体概述
简要说明用户指定的代码是做什么的，让用户建立整体认知。

#### 3.2 详细分析（主要篇幅）
针对用户阅读难点进行深入讲解，常见场景包括：

| 难点类型 | 讲解策略 |
|---------|---------|
| 变量太多、数据变换复杂 | 列清楚每个变量的用途、赋值时机、赋值后格式样例 |
| 方法调用复杂、层级太深 | 用树状图展示调用关系，由外到内理清逻辑 |
| 注释太少、逻辑晦涩 | 在复杂操作处详细讲解，补充必要的上下文 |
| 代码不规范、命名混乱 | 说明每个标识符的实际含义 |
| 算法或设计模式 | 解释核心思想和实现方式 |

**注意事项**：
- 此部分篇幅不受限制，目的是讲解清楚
- 结合具体代码行号和变量进行讲解
- 对关键逻辑和边界情况做重点说明

#### 3.3 优化建议（可选）
如果代码存在明显不合理或不规范的地方，提供重构和优化建议：
- 问题点说明
- 改进方案
- 代码示例（如适用）

**注意事项**：优化建议仅以文字形式告知用户，不要直接修改代码文件。

## 输出格式示例

```markdown
## 整体概述
[代码整体功能说明]

## 详细分析
### 1. [分析点1]
[详细讲解]

### 2. [分析点2]
[详细讲解]

...

## 优化建议（如适用）
[针对不合理代码的重构建议]
```

## 关键原则
1. **严谨性**：不盲目信任代码，自行验证逻辑正确性
2. **用户视角**：从用户最容易理解的角度出发讲解
3. **详略得当**：复杂部分详细讲解，简单部分可以略过
4. **实用导向**：帮助用户真正理解代码，而非简单复述
