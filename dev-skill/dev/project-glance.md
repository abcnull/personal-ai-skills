# project-glance

深度分析当前项目的整体架构、核心实现与技术细节，输出一份清晰易懂的项目全景解读。

---

## Input

无强制输入。用户可能的触发方式：
- "帮我分析一下这个项目"
- "这个项目是做什么的"
- "解读一下项目的技术架构"

---

## Steps

### 1. 收集项目文档

使用 **Glob** 搜索项目根目录下的文档文件（如 `README.md`、`README*`、`*.md`、`docs/` 目录等），用 **Read** 阅读找到的文档。

- 优先阅读 `README.md`（github 项目通常有）
- 如果是线下项目，可能没有 README，但可能有其他说明文档（如 `doc/`、`docs/`、`CHANGELOG.md` 等）
- 注意：忽略 `.gitignore` 中排除的文件（如 `node_modules/`、`dist/`、`.env` 等生成文件和敏感文件）
- 注意：文档信息可能过时或与代码不一致，后续需以代码为准

### 2. 分析项目文件结构

使用 **LS** 查看项目根目录结构，再用 **Glob** 递归探索关键子目录，理解项目的分层结构。

重点关注：
- 入口文件（如 `main.js`、`main.ts`、`App.vue`、`index.js`、`app.py`、`pom.xml` 等）
- 配置文件（如 `package.json`、`tsconfig.json`、`webpack.config.*`、`.env*`、`docker-compose.yml` 等） — 从中提取技术栈和依赖信息
- 目录组织方式 — 了解项目的模块划分和分层逻辑

### 3. 探究核心实现

使用 **Read** 阅读关键模块的核心文件，使用 **Grep** 或 **SearchCodebase** 搜索核心业务逻辑、路由定义、API 调用、数据流等关键模式。

重点关注：
- 核心业务流程的代码实现路径（从入口到关键逻辑的调用链）
- 项目中使用的设计模式或架构模式（如 MVC、分层架构、插件机制等）
- 项目中不太常见或独特的技术实现（用户可能不熟悉的部分）

### 4. 整理并输出分析结果

按照下方 **Output** 中的模板，将分析结果组织为结构化输出。

---

> 注意：线下项目这类问题通常较多，github 热门开源项目通常较少；如果没有明显问题则省略此章节，不要强行输出

## Guardrails

- **以代码为准** — 当文档信息与代码实现矛盾时，以代码为准，但需指出差异
- **不猜测编造** — 运行部署、PR 规范等内容必须基于实际文档或配置，不确定时明确告知用户"未找到相关文档"
- **不过度抽象** — 讲解核心流程时要落到具体文件和代码层面，不要只给抽象描述
- **突出用户不熟悉的技术** — 对项目中非常规的实现方案、少见的技术选型需重点解释，因为这通常是用户最需要了解的部分
- **信息密度优先** — 避免冗余描述，用结构化格式（标题、列表、代码块）组织内容；在不冗余的前提下，内容越详细越好，不要刻意控制篇幅
