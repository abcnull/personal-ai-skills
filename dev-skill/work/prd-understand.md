# 需求文档理解 & 回复

## 流程概述
1. 用户提供需求文档内容
2. 确认用户诉求模式（快速了解/详细探究/其他）
3. 确认用户业务熟悉程度（新手/略知一二/熟悉/其他）
4. 根据用户诉求和业务背景，解析需求并回复

## 详细流程

### 步骤1：接收需求文档
- 用户提供需求文档内容（支持Markdown格式）
- 检查文档完整性，如有明显缺失或格式问题，可询问用户是否补充

### 步骤2：确认用户诉求模式
询问用户选择以下诉求模式之一：
1. **快速了解**：希望快速掌握需求整体骨架，形成初步印象
2. **详细探究**：希望深入分析需求，详细拆解功能点
3. **其他**：用户有特定需求或问题

### 步骤3：确认用户业务熟悉程度
询问用户选择以下场景之一：
1. **新手**：对业务几乎一窍不通，需求理解困难
2. **略知一二**：了解部分业务名词，但整体理解有限
3. **熟悉**：对业务比较了解，能理解需求文档流程
4. **其他**：用户有特定背景或需求

### 步骤4：解析需求并回复
根据用户选择的诉求模式和业务熟悉程度，提供相应的解析。

## 需求解析注意事项

### 文档处理注意事项
- **格式问题**：需求文档可能是从其他地方粘贴而来，可能存在部分内容不全或格式问题
- **专业术语**：需求中可能包含业务专有名词、黑话或自定义术语，需特别注意理解
- **背景知识**：需求内容可能较多且缺少完整业务背景，可能导致理解偏差
- **文档质量**：需求文档可能存在错别字、语义问题或逻辑矛盾，但整体需求描述应清晰可理解

### 用户诉求1：快速了解
当用户希望快速了解需求时，重点解析：

1. **需求背景**：
   - 为什么需要这个PRD
   - 解决了什么问题
   - 带来什么好处

2. **整体框架**：
   - 需求主要做什么
   - 分为几个大步骤
   - 大致实现方式
   - 如果是接口调用，大致的调用链路

3. **用户使用流程**：
   - 从用户视角，串联整体使用流程
   - 用户如何触发、系统如何响应、最终输出什么
   - 用流程图或步骤描述，让用户看清完整链路

4. **表达调整**：
   - 根据用户业务熟悉程度调整表达方式
   - 对新手：尽量使用通俗易懂的语言，避免专业术语
   - 对熟悉者：可使用专业术语，表达更精炼准确

### 用户诉求2：详细探究
当用户希望详细探究需求时，除包含快速了解的内容外，还需提供：

1. **功能拆解**：
   - 识别需要实现的功能模块
   - 分析各功能模块的具体内容

2. **核心功能识别**：
   - 找出最核心、最重要的功能点
   - 分析功能之间的依赖关系

3. **实现路径**：
   - 说明各功能如何实现
   - 整体功能如何串联

4. **测试视角**：
   - 从测试角度分析需要重点关注的内容
   - 识别潜在的测试难点和风险点

### 用户诉求3：其他
当用户有特定需求或问题时：
- 针对用户的具体问题提供解答
- 如需求不明确，可进一步询问用户具体需求
- 提供用户可能需要的额外信息或建议

## 输出格式规范

### 快速了解模式输出结构
```
## 需求概述
[简要描述需求背景和目的]

## 主要内容
[需求的主要内容和框架]

## 用户使用流程
[从用户视角描述完整使用流程，串联各环节]

## 关键点
[需要特别关注的重点内容]
```

### 详细探究模式输出结构
```
## 需求背景
[详细的需求背景和目的]

## 用户使用流程
[从用户视角描述完整使用流程，串联各环节]

## 功能模块分析
### 模块1：[模块名称]
- 功能描述
- 实现方式
- 关键点

### 模块2：[模块名称]
- 功能描述
- 实现方式
- 关键点

## 核心功能
[最重要的功能点及其重要性]

## 实现路径
[整体实现流程和各模块关系]

## 测试重点
[从测试角度需要关注的内容]
```

## 示例

### 示例1：快速了解模式
用户：我想快速了解一下这个需求文档是做什么的
助手：[根据需求文档内容，提供简洁的概述]

### 示例2：详细探究模式
用户：请详细分析这个需求文档，帮我理解各个功能点
助手：[根据需求文档内容，提供详细的功能拆解和分析]
