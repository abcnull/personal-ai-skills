# 按照规范来设计技术方案文档

## 概述

本文提供技术方案文档的标准规范，需要你来根据此规范来产出技术方案文档，并输出 `dev-design.md` 到项目下的 `doc/` 目录下

## 技术方案设计

### 技术栈的选择
如果开发者有提到一些技术方案，你需要结合开发者提供的技术栈，同时分析目前的项目（如果项目已经存在一些内容的情况下），来分析该需求所适合的技术栈方向

### 整体技术文档内容设计
整片文档需要包含如下几部分：
```markdown
1. 需求文档的任务概要
2. 技术整体结构概要
    - 2.1 所使用整体技术栈能力
    - 2.2 模块划分和模块之间关系
    - 2.3 数据库表之间的依赖关联（如果需要数据库的表的话）
3. 各个模块设计细节（这里可能可以划分多个模块，不同模块是相对独立的，方便以后多个 AI agent 时同时开发）
```

## 其他要求
- 最终输出的技术方案文档为 `dev-design.md`，应该放置于项目下的 `doc/` 目录下，如果项目下无 `doc/` 目录，则需要创建
