# 按照规范来设计技术方案文档

## 概述

本文提供了编写技术方案文档的标准规范，需要你根据此规范产出技术方案文档 `dev-design.md`，并输出到此项目下的 `doc/` 内（无此目录则需创建）

## 技术方案设计

### 对技术栈的选择
- 如果开发者有提到一些技术栈，那么你需要结合开发者提供的技术栈，同时分析目前的项目（如果项目已经存在一些内容的情况下），综合分析该需求所适合的技术栈
- 如果开发者未提到任何技术栈，那么你需要分析目前的项目（如果项目已经存在一些内容的情况下），同时可以结合系统已有的环境变量，综合来分析该需求所适合的技术栈

### 整片技术文档内容包含：
1. 需求文档的任务概要
2. 整体将要使用的技术栈，以及使用这些技术栈的原因
3. 技术整体结构概要
    - 3.1 模块划分和模块间关系（流程图，架构图等）
    - 3.2 数据库还有表之间的依赖关联（如果需要数据库和表的话）
    - 3.3 其他等等
3. 各个模块设计细节（这里可能可以划分多个模块，不同模块是相对独立的，方便以后多个 AI agent 时同时开发。此处内容要求最为详细）

## 输出要求
- 最终输出的技术方案文档为 `dev-design.md`，直接存放于项目下的 `doc/` 中，如果项目下无 `doc/` 目录，则需直接帮用户创建

## 注意
- 你所产出的技术方案文档，需尽可能准确，细致无歧义，因为文档目的是为了能让后续开发者更清晰的理解该用什么工具去具体做什么事情
